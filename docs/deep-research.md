## 2. Sources explored

### 2.1. Собственный код и данные (первичный источник)

Проверено чтением кода и сохранённых страниц Avito (`tests/fixtures/`):

- **[ФАКТ] Страница выдачи содержит общее число объявлений категории** — `data-marker="page-title/count"`:
  `market_search_s104.html` → «17 888», `market_section.html` → «522 971». Парсер его **не извлекает**.
  Это бесплатный (0 доп. загрузок) ежедневный сигнал предложения по каждой категории.
- **[ФАКТ] 50 карточек на страницу выдачи**; у каждой: id, title, price, url, фото, город, дата, описание (сниппет).
- **[ФАКТ] Продавец в выдаче есть только у части карточек** (в фикстуре — `seller-info` у 15 из 50, это магазины/
  компании). У частников имени/ссылки продавца в выдаче нет → «уникальные продавцы» по выдаче честно
  не посчитать; нужна карточка (`seller-link/link`) или профиль. Это **меняет** дизайн метрики «продавцы».
- **[ФАКТ] Дата в выдаче грубая**: в фикстуре (снята в 03:49) 49 из 50 = «Вчера», 1 = «1 час назад».
  Точность — день (для свежих — часы). Инкрементальный стоп по дате ненадёжен, нужен стоп по id.
- **[ФАКТ] id объявлений растут со временем** (8357852124 у более старого, 8450818006 у более нового) —
  **[ГИПОТЕЗА]** id ≈ монотонный счётчик создания. Если подтвердится, id даёт (а) точный «водяной знак»
  новизны, устойчивый к перемешиванию/поднятиям, (б) оценку времени создания с точностью до часов
  по калибровке id→время. Проверить на собранных данных (корреляция id и даты карточки).
- **[ФАКТ] Просмотры (`total-views`, `today-views`) — только на странице карточки**; vpd = views / возраст.
- **[ФАКТ] В текущей схеме нет истории**: `categories.last_*` перезаписывается, объявления из выдачи не
  сохраняются (кроме мониторинга `listings`), `finds` — только прошедшие порог.
- **[ФАКТ] Маркеры «объявление снято» не проверены на живом Avito** (ADR-010) — «ушло за N дн» пока
  основано на непроверенных строках.

## 4. Algorithms considered

### 4.1. Инкрементальный обход и стоп

| Метод | Суть | Вердикт |
|---|---|---|
| Стоп по дате (текущий) | до первой непромо-карточки старше 7 дней | Оставить как **жёсткий** предел; для инкремента неточен (дата — день) |
| Стоп на первом известном id | — | **Нет**: промо, «поднятия», перемешивание дадут ранний стоп |
| N подряд известных id | стоп после N (≈10) подряд уже виденных непромо-id | Хорошо, но чувствителен к одному «поднятому» старому объявлению |
| Доля известных на странице | стоп, если ≥ 80–90% непромо-id страницы уже видели | Устойчиво; «stop when dry» ([MindStudio](https://www.mindstudio.ai/blog/build-scraping-skills-ai-agents-incremental-parallel)) |
| **Водяной знак id** [ГИПОТЕЗА] | новое = id > max_id прошлого sweep категории; стоп, когда на странице не осталось id выше знака | Если id монотонны — лучший вариант: устойчив к поднятиям (у поднятого объявления старый id) |
| Адаптивная глубина | pages = ceil(λ·Δt / 50 · 1.3), λ — темп новых объявлений в категории по истории | Как у Cho/Garcia-Molina: частота посещения ∝ частоте изменений |
| Частота обхода категории | тихие категории — раз в 2–3 дня, горячие — ежедневно | Да, после 7 дней истории |

**Рекомендация:** комбинированный стоп = (доля известных ≥ 0.85 **или** нет id выше водяного знака) **и** прочитана хотя бы
1 страница; плюс жёсткие пределы: 7 дней по дате и `max_pages(категория)` из адаптивной глубины.

### 4.2. Распределение бюджета карточек

| Метод | Плюсы | Минусы для нас |
|---|---|---|
| Фиксированные квоты (сейчас: ≤12 на подкатегорию, ≤2 на группу) | просто | тратит бюджет одинаково на мёртвые и живые категории |
| **Квоты по корзинам + приоритет внутри** | понятно, тестируемо, explore гарантирован | ручные доли |
| UCB | детерминированный бонус за неизученность | нужна «награда» |
| Thompson sampling ([Russo et al.](https://arxiv.org/abs/1707.02038)) | естественный explore/exploit, бета-распределение на «доля карточек ≥ порога» | имеет смысл после ~2 недель; награда шумная |
| ε-greedy | тривиально | хуже TS при той же сложности |

**Рекомендация [МНЕНИЕ]:** V1 — квоты по корзинам (baseline / новые модели / повторы / рост предложения / exploit /
recheck), приоритет внутри корзины — простая формула. Thompson sampling для **выбора категорий** в корзине
exploit/explore — V2, когда будет ≥14 дней «награды» (доля открытых карточек с attention ≥ 3×).
Это 30 строк кода (Beta(α,β) на категорию), а не ML-фреймворк.

### 4.3. Тренды и аномалии

| Метод | Мин. история | Для нас |
|---|---|---|
| Сравнение «сегодня vs вчера» с порогом на **абсолютный минимум** и пуассоновским интервалом | 2 дня | V1 (дни 1–7): только сильные изменения с большим n |
| Rolling median + MAD / modified z ([Iglewicz–Hoaglin](https://metricgate.com/docs/robust-z-score-modified/)) | 7–14 дней | **V2 (основной)**: устойчиво к выбросам, работает на коротком ряде |
| EWMA | 7+ | V2: сглаженный уровень + «ускорение» (EWMA короткая vs длинная) |
| CUSUM | 14+ | V3: накопленный сдвиг — ловит **медленный** рост, который z-score пропустит |
| Поправка на день недели | 28+ (4 недели) | V3: выходные на Avito другие |
| STL / Prophet | 2+ сезона (месяцы) | **Не нужно** в обозримом будущем |
| ruptures (offline change points) | длинные ряды | Не нужно; разве что ретроспективный анализ |
| river (online drift) | — | Избыточно для ~200 рядов раз в день |

Для **счётных** величин с малыми n (новых объявлений в нишевой категории 3→9) z-score врёт. Нужна проверка на
пуассоновской модели: рост значим, если `P(X ≥ x | λ=baseline) < 0.01` и `x ≥ x_min` (например, 5).
Это `scipy.stats.poisson.sf` или 10 строк на stdlib (`math`), новых зависимостей не нужно.

### 4.4. Нормализация товаров

| Метод | Для «Aimiko U2 Pro / AIMIKO U2PRO 48v / электровелосипед Aimiko U2 Pro» | Вердикт |

| Выделение **модельных токенов** (буквы+цифры, ≥2 символа) — уже есть `model_key`/`_model_tokens` | ключ `aimiko u2pro` | V1, расширить |

| MinHash/LSH ([datasketch](https://github.com/ekzhu/datasketch)) | масштаб сотни тысяч | Не нужно: в категории сотни–тысячи заголовков в день, O(n²) RapidFuzz укладывается |
| Мультиязычные эмбеддинги (BGE-M3, E5) | синонимы, «коляска 3 в 1» ≈ «трёхколёсная» | **Не сразу**: модель ~2 ГБ, медленно на CPU, а модели товара — это в основном латинские токены+цифры, где эмбеддинги работают **хуже** точного токена (U2 vs U3 для эмбеддинга почти одно и то же) |
| DBSCAN/HDBSCAN | кластеры без словаря | V2 поверх RapidFuzz-расстояний, если union-find будет «слипаться» |

**Позиция [МНЕНИЕ]:** нормализация + модельные токены + RapidFuzz решат ~80% задачи. Эмбеддинги — только
если замер на размеченной выборке (50–100 пар) покажет недобор. Важно: для поиска **модели** точные токены
лучше семантики; семантика нужна для **типов товаров** («коляска-трость» ≈ «прогулочная коляска»).

### 4.5. Discovery новых кластеров

Без словаря: каждый день считать по категории частоты **модельных ключей и биграмм токенов** у новых
объявлений (из выдачи, бесплатно). Событие «новый кластер», если ключ:
- в базовом окне (14 дней) встречался ≤ 1–2 раз, а сегодня/за 3 дня ≥ 5;
- в нескольких **независимых** объявлениях: разные id, разные города, разброс цен; продавцы подтверждаются
  открытием 2–3 карточек (в выдаче частник анонимен — см. §2.1);
- пуассоновский тест против фона категории.

Это классическая задача «emerging term / burst detection» на счётчиках — решается счётчиками и порогами.

### 4.6. Спрос, предложение, «продажи»

- **Предложение** (бесплатно): `total_count` категории (с pmin), новых id/сутки, доля магазинов, медиана/квартили цены.
- **Внимание** (дорого): vpd открытых карточек; лучше **дельта просмотров** между двумя замерами одной карточки
  (текущая скорость, а не средняя за жизнь).
- **«Продажи»**: исчезновение — **не** продажа. Различать:
  `sold` (статус «продано»/«забронировано» на карточке — маркер есть: «Забронировано»),
  `removed` (снято, страница «снято с публикации»), `expired` (истёк срок — Avito снимает через 30 дней),
  `relisted` (тот же продавец + похожий заголовок/цена/фото, новый id), `unknown`.
  Только `sold`/`reserved` и «исчезло **рано** (< 7 дней) при высоком внимании» — слабый прокси продажи.
- **Survival**: Kaplan-Meier ([lifelines](https://github.com/CamDavidsonPilon/lifelines)) по времени до исчезновения
  с цензурированием живых объявлений — корректно, но требует **регулярных перепроверок одних и тех же
  объявлений** (стоит загрузок). Имеет смысл через 1–2 месяца и только для топ-моделей. Архитектура: хранить
  `first_seen`, `last_seen_alive`, `gone_at`, `gone_kind` — этого достаточно.

### 4.7. Картинки

pHash/dHash ([ImageHash](https://github.com/JohannesBuchner/imagehash)) — дёшево, хорошо ловит **тот же снимок**
(relisting, перепост магазина). Победители Kaggle Avito Duplicates использовали картинки как сильный признак.
CLIP-эмбеддинги — для «та же модель, другое фото» — тяжело, позже. Фото превью уже есть в выдаче (`image_url`) —
хэш можно считать **без открытия карточки** (загрузка картинки с CDN, не страница), но это всё равно трафик
→ только для кандидатов (повторы, discovery), не для всех.

## 5. Architecture patterns

1. **Collectors → Normalization → History → Aggregation → Detection → Ranking → Report** — общий паттерн
   всех найденных систем; у монитор-проектов есть только первые два и последний шаг.
2. **Snapshot + events** (xianyu-monitor): хранить текущее состояние сущности и **события изменений**
   (появилось, цена изменилась, исчезло), а не полный снимок каждый раз. Для объявлений — то, что нужно.
3. **Incremental crawler с оценкой частоты изменений** (Cho & Garcia-Molina; Olston & Najork):
   частота посещения источника ∝ темпу изменений и ценности; оценка темпа — по своей истории.
4. **Two-tier crawl**: дешёвый широкий проход (выдача) + дорогой точечный (карточки) с отдельным бюджетом.
5. **Локальный коллектор**: браузер пользователя — единственный источник; бэкенд не ходит на сайт сам.
   Мы уже так устроены (persistent profile, ручная капча).
6. **Детекторы как чистые функции над агрегатами** — легко тестировать на синтетических рядах.

## 6. What applies to our project

1. **Сначала проверить официальную «Аналитику спроса» Avito** [ФАКТ о существовании, ГИПОТЕЗА о доступе]:
   она даёт ровно тот слой, который мы хуже всего умеем мерить скрейпингом, — **спрос по категории**
   (просмотры, **контакты**, конверсия, продавцы, объявления, средняя цена; 7/30 дней; динамика).
   Контакты — значительно лучший прокси покупки, чем просмотры, и нам **недоступен** иначе.
   Доступ: по одним источникам — бесплатно для всех (бета, 07.2025), по другим — при пакете услуг в «Товарах».
   API для неё **не найдено** → читать вручную или страницей кабинета в том же браузере (только чтение).
2. **`total_count` с каждой страницы выдачи** — бесплатный ежедневный ряд предложения по категории.
3. **Таблица `ad` (одна строка на объявление) + события**, а не снимки.
4. **Стоп по доле известных id (+ водяной знак id после проверки гипотезы)** и **адаптивная глубина**.
5. **Квотный сэмплер карточек** с корзиной baseline (случайная выборка → медиана vpd категории → Attention Multiple).
6. **Повторный замер карточек** → настоящая скорость просмотров (Δviews/Δt).
7. **Робастная статистика (median/MAD, пуассоновский тест), confidence и coverage** — без ML.
8. **Нормализация + RapidFuzz + счётчики ключей** для моделей и discovery.
9. **Wordstat** — позже, как подтверждение спроса на найденную модель (не как источник открытий).

## 7. What does NOT apply

- Прокси-пулы, ротация аккаунтов, антидетект, решатели капчи — есть почти во всех найденных скрейперах,
  **для нас запрещено** (ADR-005) и не нужно: ограничение решается экономией загрузок.
- Prophet / STL / LSTM / feature store / Kafka / Airflow / PostgreSQL — нет данных и нет масштаба.
- Эмбеддинги и HDBSCAN «с первого дня».
- Полные ежедневные снимки каждого объявления.
- Исчезновение из выдачи как сигнал продажи: мы читаем только верх выдачи, объявление «выпадает» из окна
  просто от старения. **В предыдущем аудите `category_daily.disappeared` из sweep — ошибка.**
- «Уникальные продавцы» по выдаче — частники анонимны.
- Google Trends — alpha по заявке, слабый для РФ; Reddit/YouTube — шум для этой задачи.

## 8. Risks

| Риск | Вероятность | Влияние | Митигация |
|---|---|---|---|
| Блоки Avito при росте загрузок | высокая | высокое | бюджет/день, инкремент, «информация на загрузку», ручная капча, пауза при блоке |
| Изменение вёрстки | средняя | среднее | селекторы в одном месте, фикстуры, алерт «0 карточек» |
| Ложные тренды на коротких рядах | высокая | высокое (доверие) | минимальные n, coverage, confidence, LOW первые 7 дней |
| Гипотеза «id монотонны» неверна | средняя | низкое | остаётся стоп по доле известных |
| Магазины-«спамеры» раздувают предложение | высокая | среднее | доля магазинов, дедуп по заголовку+цене+фото, продавцы в карточках |
| «Аналитика спроса» недоступна/без нужной детализации | средняя | среднее | fallback на выборочный baseline vpd |
| Пользователь не у ПК при капче | высокая | среднее | сохранение чекпойнта, продолжение позже, отчёт по тому, что успели |
| Рост `market.py` / связность | средняя | среднее | новые модули рядом; общий раннер выносить, только когда второй потребитель реально появится |

## 9. Recommendations (кратко)

1. **Неделя 0**: открыть «Аналитику спроса» в кабинете пользователя, понять детализацию и доступ.
2. Начать **копить историю немедленно**: `ad` + `category_day` (`total_count`, новые id, цены) — даже из текущего `/report`.
3. **Инкрементальный sweep** с адаптивной глубиной и устойчивым стопом.
4. **Отчёт «что изменилось» рано** (со 2-го дня) — простой, честный, с coverage/confidence.
5. Сэмплер карточек с **baseline** → Attention Multiple.
6. Модели и discovery на счётчиках.
7. Статистика трендов усложняется по мере накопления истории (V1 → V2 → V3).
8. Китай — после того, как радар стабильно выдаёт модели.

```
   SWEEP (выдача, дёшево)                                         DEEP (карточки, дорого)

          │                                                        exploit / explore / recheck
          ▼                                                                 ▼
   ad (1 строка/объявление) + ad_event (цена/исчезло)          card_obs (views, today, seller, date)
          └───────────────┬─────────────────────────────────────────────────┘
                          ▼

                          ▼
            Daily Radar (Telegram, одно сообщение) + /top /export /price (без изменений)
```
