# Product Hunter — финальный blueprint

Дата: 2026-10-04. Статус: **ждёт команды на реализацию**. Код не менялся.
Главный продукт: **каждое утро 5–10 конкретных моделей**, которые стоит проверить в Китае и выставить на Avito.
Категории — только способ найти эти модели. Спрос — гипотеза, пока его не подтвердили данные Avito,
а потом — твои собственные объявления.

```
CORE/WATCH/QUERY search → все свежие объявления в ads → нормализация заголовков → бренд+модель →
кластеры товаров → дешёвые кандидаты (без карточек) → выборочные карточки → просмотры/день →
внимание к норме категории → TOP 5–10 + EMERGING → ты проверяешь Xianyu/Taobao/1688 → выставляешь →
свои просмотры/избранное/контакты/заказы → обратно в Product Hunter
```

## 6. Генерация кандидатов (без карточек → потом карточки)

Кластер = объявления с одним ключом «бренд + модель» (разные `external_id`, нормализация заголовка).

| Путь | Условие (стартовые значения) |
|---|---|
| **A. REPEATED** | ≥ 3 объявления за 14 дн **и** ≥ 2 независимых источника (разные города или разные магазины) **и** медианная цена ≥ 8 000 |
| **B. EMERGING** | кластер впервые появился ≤ 5 дн назад **и** (≥ 2 объявления за 72 ч **или** цена ≥ p75 категории **или** поток кластера за 3 дн ≥ 2× его нормы за 7 дн) |
| **C. ATTENTION** | любая открытая карточка (база или чужой кандидат) показала внимание ≥ 3× нормы категории → её кластер становится кандидатом |

Не кандидат: 👎 за последние 30 дней; > 80% объявлений кластера у одного магазина (помечается, не скрывается совсем);
цена < 8 000.

Карточки: на кандидата — 1 самая свежая; вторая, если первая дала 1–3× (неоднозначно); не открывать, если замер
моложе 24 ч. Чек (медианная цена) — сигнал сортировки, не порог: 50–100k выше 9k при прочих равных.

**Внимание** = просмотры/день объявления ÷ норма категории (медиана базы, при < 10 замерах «стянута» к медиане
раздела). Просмотры/день — только у объявлений старше 12 ч.

**Порядок вывода** (объяснимый, без итогового числа): 1) кандидаты с вниманием ≥ 2× и уверенностью ≥ MEDIUM;
2) внутри — больше независимых продавцов; 3) выше чек; 4) свежее. Уверенность: HIGH — ≥ 2 карточки, ≥ 3 объявления,
норма категории ≥ 10 замеров; MEDIUM — 1 карточка и норма ≥ 5; иначе LOW → раздел EMERGING.

## 9. Новые таблицы/поля (только нужные)

```sql
-- область обхода
ALTER TABLE categories ADD kind TEXT DEFAULT 'category';   -- category | query
ALTER TABLE categories ADD scope TEXT DEFAULT 'OFF';       -- CORE | WATCH | QUERY | EXPLORE | OFF | HARD_EXCLUDE
ALTER TABLE categories ADD scope_status TEXT;              -- hypothesis | confirmed (для CORE)
ALTER TABLE categories ADD flags TEXT;                     -- 'LOGISTICS_CHECK,REGULATORY_CHECK,FAKE_RISK'
-- срезы не «присваивают» объявления
ALTER TABLE ads ADD query_id INTEGER;

-- жизненный цикл товара (и будущая обратная связь)
CREATE TABLE products (
  id INTEGER PRIMARY KEY, key TEXT UNIQUE,                 -- нормализованный бренд+модель
  label TEXT, first_seen_at TIMESTAMP,
  status TEXT DEFAULT 'new',                               -- new | candidate | checking | listed | rejected | dropped
  status_at TIMESTAMP, suppressed_until DATE, note TEXT);
CREATE TABLE candidate_log (                               -- что и почему показали (объяснимость, без повторов)
  day DATE, product_id INTEGER, path TEXT,                 -- repeated | emerging | attention
  metrics TEXT /* JSON: цена, объявления, продавцы, города, внимание, рост, свежесть, уверенность */,
  shown INTEGER, PRIMARY KEY (day, product_id));
```
`card_obs.bucket`: `baseline` · `candidate` · `recheck`. Будущая фаза (не сейчас): `own_listings(product_id,
avito_item_id, listed_at)` + `own_listing_stats(item_id, day, views, favorites, contacts)` через Avito API —
схема `products.status = listed` её не блокирует.
